
# RUACH — Machine Learning Pathway
## Product Goals and Acceptance Criteria

**Release:** Learning & Engineering Growth
**Pathway:** Machine Learning
**Status:** Proposed

---

# 1. Product Objective

Build a structured, practical and progressive Machine Learning pathway that develops learners from foundational mathematical and programming knowledge into competent practitioners capable of developing, evaluating, deploying and maintaining machine learning solutions.

The pathway must provide more than educational content.

It must help learners develop demonstrable competencies through:

- Structured learning.
- Practical coding exercises.
- Conceptual assessments.
- Experimentation.
- Guided projects.
- Independent projects.
- Real-world engineering scenarios.
- Evidence-based skill progression.

# 2. Product Goals

## G0 — Establish a Distinct ML Learning Experience

**Goal:** Machine Learning must exist as a first-class pathway within RUACH, distinct from AI Engineering.

### Requirements

- Dedicated ML dashboard and learning path.
- Dedicated curriculum structure.
- ML-specific progress tracking.
- ML-specific competencies.
- ML-specific exercise categories.
- ML-specific project templates.
- ML-specific assessment criteria.

### Acceptance criteria

- Learners can enter the ML pathway independently.
- ML and AI Engineering progress are tracked separately.
- Learners can identify the prerequisites and expected outcomes of each module.
- Shared infrastructure does not cause the pathways to become indistinguishable.

## G1 — Develop Strong Mathematical and Statistical Foundations

**Goal:** Help learners understand the mathematical reasoning behind machine learning.

### Requirements

- Progressive mathematics curriculum.
- Statistics and probability curriculum.
- Visual explanations of mathematical concepts.
- Interactive mathematical exercises where appropriate.
- Practical connections between mathematics and ML algorithms.

### Acceptance criteria

- Mathematical concepts have clear learning objectives.
- Learners can apply foundational statistical calculations.
- Learners can interpret distributions and statistical summaries.
- Learners understand vectors, matrices and gradients at an appropriate introductory level.
- Learners can connect gradient descent to model training.

### Success indicators

- Assessment performance on mathematical and statistical exercises.
- Ability to explain concepts in plain language.
- Successful completion of practical mathematics exercises.

**Goal:** Ensure learners can assess model quality using appropriate and defensible methods.

### Requirements

- Regression and classification metrics.
- Cross-validation.
- Model comparison.
- Hyperparameter tuning.
- Error analysis.
- Bias and variance.

## G7 — Create an Evidence-Based ML Skill Passport

**Goal:** Track what learners can actually demonstrate rather than relying solely on lesson completion.

### Requirements

The ML Skill Passport should track competencies across:

1. Mathematics and statistics.
2. Python programming.
3. Data analysis.
4. Data preparation.
5. Feature engineering.
6. Supervised learning.
7. Unsupervised learning.
8. Model evaluation.
9. Deep learning.
10. ML deployment.
11. MLOps.
12. Responsible ML.

### Evidence sources

- Completed practical exercises.
- Assessment results.
- Project submissions.
- Experiment reports.
- Code reviews.
- Deployment evidence.
- Tutor-assisted explanations.
- Verified independent demonstrations.

### Acceptance criteria

- Each competency has defined evidence requirements.
- Lesson completion alone does not establish mastery.
- Evidence records identify the assessment or project that supports the competency.
- Learners can see their demonstrated strengths and outstanding competencies.
- Skill levels distinguish exposure, practice, proficiency and mastery.

## G8 — Deliver ML-Aware AI Tutor 2.0

**Goal:** Make the shared tutor useful for mathematical reasoning, data analysis, algorithm understanding and model experimentation.

### Requirements

The tutor should support:

- Mathematical explanations.
- Step-by-step statistical reasoning.
- Python and data science debugging.
- Algorithm explanations.
- Model evaluation interpretation.
- Experiment design.
- Error analysis.
- Project guidance.

### Behavioural requirements

- Use progressive hints.
- Encourage learners to reason before revealing solutions.
- Explain concepts at the learner's current level.
- Identify misconceptions.
- Interpret code and error messages.
- Explain model behaviour without pretending to know more than the supplied evidence supports.

### Acceptance criteria

- Tutor responses are evaluated for correctness and usefulness.
- ML-specific context is available when appropriate.
- Learners can request hints without immediately receiving full solutions.
- Mathematical explanations include relevant examples.
- Tutor feedback distinguishes verified conclusions from hypotheses.

# 3. Non-Functional Goals

## Reliability

- Learning progress must persist reliably.
- Exercise submissions must not silently disappear.
- Project and experiment records must remain associated with the correct learner.
- Failures must be recoverable where possible.

## Security

- Protect uploaded datasets and project files.
- Validate file types and sizes.
- Prevent arbitrary code execution on the main application server.
- Enforce appropriate access controls.
- Avoid exposing private datasets or credentials.
- Apply resource limits to computational workloads.

## Performance

- Avoid unnecessary loading of large datasets.
- Provide clear feedback during long-running operations.
- Keep ordinary lesson and exercise interactions responsive.
- Design compute-heavy activities to run through appropriately isolated infrastructure.

## Accessibility

- Mathematical content should be readable.
- Charts should include meaningful descriptions.
- Colour must not be the only means of communicating information.
- Interactive exercises should support accessible navigation.

## Maintainability

- Curriculum content should be data-driven.
- Exercise definitions should be versionable.
- Learning objectives and assessments should be independently maintainable.
- Shared services should not become tightly coupled to one pathway.

# 4. Explicit Non-Goals

The initial release does not need to provide:

- A complete university-level mathematics programme.
- A distributed GPU training platform.
- A proprietary ML framework.
- A replacement for PyTorch or TensorFlow.
- An unrestricted cloud notebook environment.
- Arbitrary public dataset scraping.
- Production-scale model hosting.
- Fully automated claims of professional ML competence.
- An autonomous system that makes unreviewed model deployment decisions.

# 5. Overall Product Success

The ML pathway is successful when learners can move beyond following tutorials and demonstrate that they understand the complete machine learning workflow:

**Problem → Data → Preparation → Model → Evaluation → Experimentation → Deployment → Monitoring**

The ultimate measure is not the number of lessons completed. It is the quality, correctness and independence of the work learners can demonstrate.
