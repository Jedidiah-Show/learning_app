# RUACH LMS 1.1.0 — Learning Intelligence & Engineering Excellence

**Release type:** Major consolidation (baseline: Parallel Pathways 1.0.0 @ `68b3125`)
**Status:** Engineering complete through M6; release gate (M7) in verification.
See `docs/RELEASE_STATUS.md` for the authoritative exit-criteria ledger.

## Highlights

- **Three-domain architecture enforced end to end.** Shared Foundations,
  AI Engineering and Machine Learning resolve independently through a
  canonical registry (`app/curriculum_registry.py`); cross-specialisation
  dependencies are rejected at load time.
- **Shared Foundations is a real pathway.** Validated lesson manifest,
  sequential lesson resolution, a standalone lesson route, and honest
  pending states until human-authored content ships module by module.
- **Practice Arena 2.1.** Machine Learning grew into 14 topic domains
  (330 problems, all validated), topics map to curriculum domains, and
  submissions record a challenge content version.
- **Skill Passport 2.1.** learner/reviewer/instructor/administrator roles,
  separation of duties (nobody verifies their own evidence), append-only
  verification history, and a learner interface with badges, reviewer
  notes, actions and history.
- **Project Studio 3.0.** Manifest-driven ML project pages (no hardcoded
  copy), AI Engineering-specific project schema and artefacts, a shared
  lifecycle engine with an append-only audit log, and project milestones
  derived from published deliverables.
- **AI Tutor 3.0.** Ordered domain resolution (explicit context →
  registry lesson domain → practice problem → project domain → active
  pathway), seven instructional modes with aliases, permission-controlled
  persistent context, and a structural evaluation gate.
- **Learning Intelligence.** Concept-level mastery derived from
  authoritative evidence only; explained recommendations; mastery
  dashboard; spaced repetition integrated.
- **Release integrity.** Fail-closed source export with checksum and
  manifest; secret scanning in CI; release metadata (`/version`);
  `/healthz` + `/readyz`; fresh-SQLite upgrade **and** downgrade verified
  end to end.

## Security posture

Authoritative evidence: learners cannot verify their own credentials;
assessment operations require a privileged reviewer and a distinct target
learner. Credential rotation for pre-existing local secrets is recorded in
`docs/SECURITY_REMEDIATION_REPORT.md` and must be executed by the release
owner before deploying 1.1.0.

## Known limitations

- Shared Foundations lessons ship as `pending` until authored and reviewed.
- The isolated judge ships disabled by default (`JUDGE_SUBMISSIONS_ENABLED`);
  Submit honestly returns 503 until the judge worker and image are deployed.
- Live model-backed tutor evaluation is pending a working provider key;
  structural evaluation gates pass.
- Latency/cost baselines for the tutor are recorded as unmeasured.
- Browser E2E for full learner journeys is covered only in CI (Node 20 +
  Chromium); local runs need Node ≥ 20.
